# ADR-0018: react-native-svg draws charts

- Status: Active
- Date: 2026-11-04
- Decision makers: Project owner
- Recorded ahead of the work it governs.

## Context

The Deck statistics screen's **Session history** chart is to become a smooth stacked **area**
chart — one band per answer and one for unanswered cards, joined by curves from session to session
([ADR-0015](0015-answers-carry-a-timestamp-under-v2-keys.md) Amendment 3). Today it is a row of
stacked columns built from `View`s in
[`src/components/SessionHistoryChart.tsx`](../../../src/components/SessionHistoryChart.tsx).

Nothing in the app can draw that chart:

- **Every icon is nested `View`s**, apart from the category icons, which are Android vector
  drawables shown by `Image` ([ADR-0013](0013-category-icons-are-android-vector-drawables.md)).
  A drawable is a fixed asset compiled at build time; it cannot draw a shape computed from data.
- **A `View` draws rectangles** — with borders, rounded corners and transforms — but **no curve
  and no arbitrary filled region**. A stacked area band is a region bounded by two curves.
- **The `backgroundImage` gradient style** of this React Native version, already used for
  gradients in the app, **paints a `View`'s rectangle only**. It cannot fill the area under a
  curve.

So the chart needs a drawing library, and this would be the app's **first third-party drawing
dependency**. The dependency list is short on purpose, and two entries on it exist because the
obvious library did not work (`AGENTS.md` *Dependency traps*); adding one needs the owner's
approval and an ADR.

**The project owner approved `react-native-svg@^15.16.0` on 2026-11-04.**

What was checked about that version before recording this:

- **React Native.** 15.16.0 supports React Native 0.80 and later, and its CI covers
  0.88.0-rc.5; this project's version is in [`package.json`](../../../package.json). The
  package's `peerDependencies` are `react: *` and `react-native: *`, so npm will not warn when a
  future React Native upgrade leaves the supported range.
- **React 19.** Every `defaultProps` in the package is set on a **class** component, which React 19
  still honours. The trap that rules out `react-native-render-html` — `defaultProps` on function
  components, silently ignored ([ADR-0001](0001-own-the-html-renderer.md)) — does not apply.
- **Native code.** It is a native package: its components are generated by React Native's codegen
  and built with CMake, and it is autolinked. It brings `css-tree` and `css-select` as JavaScript
  dependencies, for its XML and CSS entry points.

## Decision

**`react-native-svg` draws the app's data charts**, starting with the Session history chart on
the Deck statistics screen. A later data chart uses it too, rather than a second drawing library.

### What it is not for

- **Icons.** Every icon stays drawn from nested `View`s, and the category icons stay Android vector
  drawables shown by `Image`. ADR-0013 is unchanged (its Amendment 3); a new icon is not a reason
  to draw it with SVG.
- **Card content.** [ADR-0001](0001-own-the-html-renderer.md) is unchanged: both sides of a card
  are parsed by [`src/utils/html.ts`](../../../src/utils/html.ts) and rendered by
  [`RichText`](../../../src/components/RichText.tsx) as nested `Text`. SVG is not a rendering path
  for card HTML.
- **Imported content, ever.** `SvgXml`, `SvgCss`, `SvgUri` and `SvgCssUri` are never given anything
  that came from an imported deck. A deck file is untrusted input
  ([ADR-0017](0017-deck-import-reads-exported-formats.md)), and `SvgUri` / `SvgCssUri` fetch their
  source over the network, which this app never does.

### Rules for a chart

- **Import `react-native-svg` only from `src/components/`.** A screen renders a chart component;
  no screen, `src/utils/`, `src/state/`, `src/storage/`, `src/services/` or `src/types.ts` imports
  the package.
- **Chart geometry is pure TypeScript in `src/utils/`, and Jest-tested.** For the Session history
  chart that is `src/utils/historyChart.ts`: it takes the data and a size in dp and returns the
  paths, points and label positions. The component only turns that geometry into SVG elements and
  React Native `Text`. The geometry module imports neither `react`, `react-native` nor
  `react-native-svg`, as everything in `src/utils/` does.
- **No SVG filters** (`Filter` and the `Fe*` primitives). On Android they rasterise through
  RenderScript, deprecated since API 31. A soft shadow under a line is a wider, translucent
  **underlay stroke** drawn beneath it.
- **No SVG `Text` for anything the user reads.** SVG text ignores the system font scale. Axis
  labels, values and legends are React Native `Text`, absolutely positioned from the coordinates
  the geometry returns.
- **The SVG subtree is hidden from accessibility**, and React Native elements around it carry the
  labels and the summary a screen reader announces.
- **Measure, then draw in dp.** The chart's width comes from `onLayout`, and the geometry is
  computed at that width. Do not draw into a fixed `viewBox` stretched with
  `preserveAspectRatio="none"`: it distorts strokes and markers unevenly, and the React Native labels
  would no longer line up with what is drawn.

## Alternatives Considered

- **Keep the stacked columns of `View`s.** The status quo, no dependency. Rejected: `View`s cannot
  draw curves or fill a region under one, so the area chart cannot be built.
- **`@shopify/react-native-skia`.** A full 2D canvas that can draw anything, filters included.
  Rejected: much heavier — a larger native library and its own rendering surface — for charts that
  need paths, gradients and circles.
- **A chart library on top of SVG or Skia** — `react-native-gifted-charts`, `victory-native`.
  Rejected: each still brings SVG or Skia, then adds its own layer of components and options on
  top: more dependencies, a bigger maintenance surface in a list kept short on purpose, and labels,
  font scaling and accessibility decided by the library rather than by the rules above.
- **A WebView with an HTML or JavaScript chart.** Rejected: another native dependency, a browser
  engine for one chart, data passed across a bridge, and text and accessibility outside React
  Native. It is also the kind of component that invites network access.

## Consequences

### Positive

- The Session history chart, and any later chart, can draw curves, filled bands and gradients.
- Chart geometry is a pure function, so the arithmetic that places every band, marker and label is
  unit-tested, as the rest of `src/utils/` is.
- Labels follow the system font scale and accessibility works as it does on every other screen,
  because both stay React Native.
- One drawing library for charts, instead of a choice made per chart.

### Negative

- **A new native dependency.** Installing it needs a native rebuild — codegen and a CMake build —
  and a Metro reload does not pick it up. The APK grows.
- **It must add no Android permission or manifest entry.** None is expected, but approving a
  dependency is not approving what it merges into the manifest (`AGENTS.md` *What to ask before
  doing*). The definition-of-done gate checks the merged manifest of the built APK.
- **iOS would need `pod install`.** The iOS project is not built today, so this costs nothing now.
- **Jest cannot load it as configured.** The preset's `transformIgnorePatterns` does not match
  `react-native-svg`, so a future component test that imports a chart needs the pattern widened and
  the package mocked. No test imports a component today, so nothing breaks now; the chart
  component itself is covered only by looking at it on a device.
- **Compatibility is not enforced by npm.** With `*` peer ranges, every React Native upgrade has to
  check the package's supported versions by hand.
- **"How is this drawn?" has a third answer** — `View`s, vector drawables, and now SVG for charts.
  The carve-outs above say which is which.
- **A chart draws after layout.** It has no width until `onLayout` fires, so it reserves its height
  and draws on the following frame.

### Not decided here

- Animating a chart. Nothing animates one, and no animation library is added.
- Which other figures become charts. Charts over time on the Statistics screen are still undecided
  ([ADR-0015](0015-answers-carry-a-timestamp-under-v2-keys.md) Amendment 2).
